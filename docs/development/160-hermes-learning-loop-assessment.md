## Hermes 的闭环是什么(机制,非宣传)

三件套 + 一套门控,全部由 agent 自己驱动:

| 环节     | 机制                                                                                                                                                                                                                                                    |
| -------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------- | ----------------------------------------------------------------------------------- |
| 技能环   | 系统提示指示 agent 在「值得重复的多步流程/从错误中恢复的路径/被用户纠正的做法」出现时,经 `skill_manage` 工具保存技能;每轮结束后**后台复盘**(可跑便宜 3-5 倍的辅助模型)可代存/改技能;`/learn` 重跑同主题会折叠进既有技能而非新建;改用定向 patch 省 token |
| 记忆环   | 同一后台复盘顺带沉淀「小而持久、应常驻上下文的事实」;周期性 nudge(`memory.nudge_interval` 配置)提醒 agent 持久化知识                                                                                                                                    |
| 会话搜索 | 全部会话入 SQLite(`~/.hermes/state.db`)FTS5 全文索引;agent 有 `session_search` 工具(discovery/scroll/browse 三形态,~20ms 查询 ~1ms 滚动);**原文返回,不做 LLM 摘要**(文档明说)——记忆管要点,搜索回忆细节                                                  |
| 门控     | `skills.write_approval`/`memory.write_approval`:写入先落 pending 目录(跨重启),`/skills diff                                                                                                                                                             | approve | reject` 审;staged 补丁的目标条目若已被改动则拒写防冲突;advisory linter 只警告不阻塞 |

分工哲学:记忆=常驻小事实,技能=按需加载的长流程,会话搜索=原始细节兜底。用户建模(Honcho 等外部 provider)是可选插件,非内置。

## 与 ZCode-CE 现状映射

| Hermes 能力                         | ZCode-CE 现状                                                                                 | 差距                                                                         |
| ----------------------------------- | --------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------- |
| `skill_manage`(agent 自存/自改技能) | **已有 SkillManage**(feiyu 吸收,personal skills create/patch,create 需用户批准)               | 缺:后台复盘触发、同主题折叠、pending 审批流(approve/diff/reject)、定向 patch |
| agent 记忆                          | **已有**(file-based memory + MEMORY.md 索引,agent 主动写)                                     | 缺:轮后后台复盘、周期 nudge、写入门控(当前自动写)                            |
| FTS5 会话搜索                       | **无 agent 侧工具**——会话有 sqlite(tasks-index/sessions-index,UI 侧)但 agent 没有跨会话检索面 | 整块缺失                                                                     |
| 用户建模(Honcho)                    | 无                                                                                            | 不吸收(外部云 provider,隐私形态不符)                                         |

## 决策表

| 项                                         | 决策                 | 理由                                                                                                                                                    |
| ------------------------------------------ | -------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **P1:session_search(FTS5 跨会话搜索工具)** | **列为首个实现候选** | 我们已有全部会话数据(CLI session store + UI 侧 sqlite),缺的只是 agent 可调的只读检索面;Hermes 证明「原文返回不摘要」就够用;独立、小、不动 turn 生命周期 |
| P2:轮后后台复盘(便宜模型代存记忆/技能)     | 决策项,待对齐        | 价值真实(自动沉淀)但动 turn 生命周期+引入辅助模型计费面;且我们的记忆已默认由 agent 主动维护,增量比 Hermes 小                                            |
| P3:SkillManage pending 审批流 + 同主题折叠 | 决策项,待对齐        | 现有 create 需批准已覆盖交互态;pending 流主要服务无人值守写入(P2 的前置),单做收益有限                                                                   |
| Honcho/外部记忆 provider                   | 不吸收               | 云端第三方用户画像,与本地优先形态不符                                                                                                                   |
| advisory linter                            | 不吸收               | 锦上添花, ours 技能量级还小                                                                                                                             |

## P1 落点预研(立项时展开)

- 数据源:CLI 侧 session store 为准(与 UI 侧索引的一致性以 session-management skill 的不变量为准,不建第二份事实);
- 面的形态:只读工具(名称暂定 `session_search`),FTS5 索引建于既有 sqlite 或旁路只读索引,写入路径不动;
- 安全:搜索结果只含本 workspace identity 的会话(workspaceIdentity 隔离纪律),凭据/敏感字段不进索引(日志纪律同源)。
