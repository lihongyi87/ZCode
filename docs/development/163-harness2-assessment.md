# 163 · Google Harness² 评估(递归 harness 自优化)

状态:评估完成——**框架整体不移植;「对比探针门控」登记为 spec 160 P2(后台复盘)的机制升级方案**(2026-10-28)
来源:`google-research/harness2`(Apache-2.0,~20.7k stars,Python,2026-10-09 发布,main 仅 3 commits——研究原型而非产品)。论文 arXiv:2610.14224(Google Cloud AI Research + Northwestern)。

## 它是什么

不改模型权重,把 **harness 本身当作可优化对象**:定义 8 个可编辑组件(system prompt / guardrails / memory / tool guidance / subagents / skills / scripts / plugins),用「编辑器模型」对它们做迭代搜索——

- **Propose**:基线 harness 跑一次任务作参照;两个编辑器各起草候选(通用编辑器盯跨域弱点如规划/委派,领域编辑器带本领域知识流程);
- **Probe**:两个候选在同一任务、同设置下各跑一次,与参照做**行为对比**——不需要标准答案,只看「这次编辑有没有改变它针对的行为」;
- **Compose**:只把有证据支持的编辑合并进后继 harness;
- **持久层**:被采纳的 harness + 证据支撑的 lessons 文件进持久库,喂给后续任务的 Propose;每个任务仍从同一基线出发。

效果声明(其自测):GLM-5 64.2→75.7(WorkBuddy),超过 Gemini 3.5 Flash 基线——**更好的 harness 能胜过更好的模型**;k=5 并行递归再 +2.6~6.7 分。

## 与 ZCode-CE 的映射

**八件套我们全部已有,且同样是文件形态**——这是对本仓架构的强佐证,不是差距:

| Harness² 组件 | ZCode-CE 等价物                                         |
| ------------- | ------------------------------------------------------- |
| system prompt | AGENTS.md + 系统提示装配                                |
| guardrails    | hooks + permission-flow + 铁律段                        |
| memory        | agent 记忆(MEMORY.md 索引+文件)                         |
| skills        | SKILL.md 体系                                           |
| tool guidance | 工具描述(js 提示/KbSearch/SessionSearch 文案)+ kb-cards |
| scripts       | .zcode/scripts + 技能脚本                               |
| subagents     | agent team / subagent 运行时                            |
| plugins       | 插件体系(plugin-creator)                                |

**我们缺的只有一件事**:让这些文件自动演化的**证据门控**。Hermes 评估(spec 160)P2 的后台复盘目前只有「便宜模型建议」这一半;Harness² 补上了另一半——**写入前先对比探针**:候选改动在同类任务上与现状各跑一遍,行为有可证改进才落盘。

## 如实边界

- Harness² 的「self-improving」= 对模型外围文件的迭代搜索+持久教训库,**不是**权重更新或合成训练数据——与本仓吸收 Hermes 时对「学习循环」的理解一致,无神秘成分。
- 其自述风险:执行器网络不受限、评测 rubric 可能在线可达——基准数字要打折看;且 single-step 之外 k 递归的收益(2.6~6.7)是在其自建基准上。
- spec 160 P2 若立项,算力形态是「bench 子集探针」(每次技能/记忆写入前跑小样本),不是 Harness² 的全量递归搜索;预期收益上限也相应小得多——它证明的是方向,不是我们的预期值。
